# `Scaled Dot-Product Attention`：理论知识

## 1. 作用与目的

`Scaled Dot-Product Attention` (缩放点积注意力) 是 Transformer Block 中**自注意力 (Self-Attention) 子层** 内部的**主要计算公式**。

它的**核心目的**是回答这个问题：

> “对于序列中的**某一个** token（由其 Query 向量 $Q$ 代表），它应该**多大程度**地‘关注’序列中的**所有** token（包括它自己，由它们的 Key 向量 $K$ 代表）？”

它通过计算一系列的**注意力权重 (Attention Weights)** 来回答这个问题。

一旦计算出这些权重（`softmax` 的输出），它就会用这些权重去对所有 token 的 **Value 向量 $V$**（代表 token 的实际内容）进行**加权求和 (Weighted Sum)**。

**最终输出**：对于序列中的**每一个** token，它都会输出一个新的向量。这个新向量不再仅仅是它自己，而是**一个融合了它所“关注”的所有其他 token 信息的“混合向量”**。这就是 Transformer 如何实现 token 之间的信息交流的。

## 2. 数学原理 (讲义 §3.5.4, 公式 11)

`Scaled Dot-Product Attention` 的计算公式如下：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$

这个公式看起来复杂，但我们可以把它分解为 5 个清晰的步骤：

* **输入**：`Q` (Query), `K` (Key), `V` (Value) 三个矩阵。
    * `Q` 的形状：`(..., seq_len_q, d_k)`
    * `K` 的形状：`(..., seq_len_k, d_k)`
    * `V` 的形状：`(..., seq_len_k, d_v)`
    *(注：`...` 代表所有前导维度，如 `batch_size`, `num_heads`。在自注意力中，`seq_len_q` 和 `seq_len_k` 通常相同，`d_k` 和 `d_v` 也通常相同)*

---

**步骤 1：计算原始分数 (Raw Scores)**
* **公式**：$QK^T$
* **操作**：将 `Q` 矩阵乘以 `K` 矩阵的**转置** (`K^T`)。
    * `Q` 形状 `(..., seq_len_q, d_k)`
    * `K^T` 形状 `(..., d_k, seq_len_k)`
    * **结果**：得到一个形状为 `(..., seq_len_q, seq_len_k)` 的**注意力分数矩阵**。
* **含义**：矩阵中的 `[i, j]` 位置的值，代表第 `i` 个 Query token 与第 `j` 个 Key token 之间的**原始相关性得分**（通过点积计算）。

**步骤 2：缩放 (Scaling)**
* **公式**：$\frac{...}{\sqrt{d_k}}$
* **操作**：将上一步得到的**所有**分数**除以** $\sqrt{d_k}$（$d_k$ 是 Q/K 向量的维度，例如我们之前讨论的 `d_head=32`）。
* **为什么需要缩放？**
    * 这是一个**非常重要**的**数值稳定性**技巧。
    * 随着 $d_k$ 维度变大（例如 64, 128），$QK^T$ 点积的结果的**方差**会增大，导致一些分数变得**非常大**（或非常小）。
    * 将这些大分数输入 `softmax` 时，`softmax` 会变得“饱和”——它会给那个最大的分数值**几乎 100%** 的概率，而给其他所有值**几乎 0%** 的概率。
    * 这会导致**梯度消失**（梯度变为 0），模型无法学习。
    * 除以 $\sqrt{d_k}$ 可以将分数的方差重新拉回到 1 附近，使得 `softmax` 的输出更平滑，梯度更稳定，训练得以继续。

**步骤 3：应用掩码 (Masking) (可选)**
* **操作**：在送入 `softmax` **之前**，应用一个**掩码 (mask)** 矩阵。
* **目的**：**强制**模型**不能**关注某些 token。
* **如何实现**：对于所有**不允许**关注的位置（`mask` 矩阵中为 `False` 的地方，例如一个 token 不应该关注它**未来**的 token，这就是**Causal Masking**），我们将这些位置的缩放后分数**设置**为一个**非常大**的**负数**（例如 `-1e9` 或 `float("-inf")`）。
* **为什么这能行？**：因为下一步 `softmax` 会计算 $e^{\text{score}}$。$e^{-\infty}$ 的结果**是 0**。这确保了被掩码的位置在最终的注意力权重中**占比为 0%**。

**步骤 4：归一化 (Softmax)**
* **公式**：$\text{softmax}(...)$
* **操作**：对（可能已被掩码的）缩放后分数矩阵，沿着**最后一个维度**（即 `seq_len_k` 维度），应用我们刚刚实现的 `softmax` 函数（包含减去最大值的技巧）。
* **结果**：得到**注意力权重矩阵**（形状 `(..., seq_len_q, seq_len_k)`）。矩阵的每一行（代表一个 Query）现在都是一个**概率分布**，所有值都在 0 和 1 之间，且**每行之和为 1**。

**步骤 5：加权求和**
* **公式**：$... V$

* **操作**：将上一步得到的**注意力权重矩阵**（形状 `(..., seq_len_q, seq_len_k)`）与 **Value 矩阵 `V`**（形状 `(..., seq_len_k, d_v)`）进行矩阵乘法。

* **结果**：得到最终的**输出张量**，形状为 `(..., seq_len_q, d_v)`。

* **含义**：输出张量中的**第 `i` 行**（`output[..., i, :]`），现在是**所有** `V` 矩阵行的**加权平均值**，权重就是注意力权重矩阵的**第 `i` 行**。这完成了 token 间的信息融合。

* **举例说明**

  这个过程就是一步**矩阵乘法**：`Output = Attention_Weights @ V`。我们来把它拆解开：

  假设 `seq_len=3`（例如 "dog bites man"），`d_v=4`（为了简单）。

  **1. `V` (Value) 矩阵 (形状 `(seq_len_k, d_v)` 即 `(3, 4)`)**
  `V` 矩阵包含了**所有** token 的“内容”向量：

  ```
  V = [
        [10, 20, 30, 40],  # V_0 (代表 "dog" 的内容向量)
        [50, 60, 70, 80],  # V_1 (代表 "bites" 的内容向量)
        [90, 100, 110, 120] # V_2 (代表 "man" 的内容向量)
      ]
  ```

  **2. `Attention_Weights` 矩阵 (形状 `(seq_len_q, seq_len_k)` 即 `(3, 3)`)**
  这是 `softmax` 计算后的结果。我们只看**第 `i=0` 行**（即 "dog" 应该关注谁）：

  ```
  Attention_Weights = [
                        [0.8, 0.1, 0.1],  # 第 i=0 行 ("dog" 对 "dog", "bites", "man" 的权重)
                        [ ... ],          # 第 i=1 行
                        [ ... ]           # 第 i=2 行
                      ]
  ```

    * **您是对的**：`Attention_Weights` 的第 `i=0` 行是**很多数**：`[0.8, 0.1, 0.1]`。

  **3. 计算 `Output` 矩阵 (形状 `(seq_len_q, d_v)` 即 `(3, 4)`)**

  `Output = Attention_Weights @ V`

  我们现在只计算 `Output` 的**第 `i=0` 行** (`Output[0, :]`)：

  `Output[0, :]` = ( `Attention_Weights` 的**第 0 行** ) **@** ( **整个** `V` 矩阵 )  \<- 这是矩阵乘法的定义

  这在数学上等同于：

  `Output[0, :]` = (`Attention_Weights[0, 0]` ***** `V[0, :]`) +
  (`Attention_Weights[0, 1]` ***** `V[1, :]`) +
  (`Attention_Weights[0, 2]` ***** `V[2, :]`)

  代入我们的**数值**：

  `Output[0, :]` = ( **`0.8`** ***** `[10, 20, 30, 40]` ) +
  ( **`0.1`** ***** `[50, 60, 70, 80]` ) +
  ( **`0.1`** ***** `[90, 100, 110, 120]` )

  **执行计算**：

    * `0.8 * [10, 20, 30, 40]` = `[ 8, 16, 24, 32 ]` (80% 的 "dog" 内容)
    * `0.1 * [50, 60, 70, 80]` = `[ 5,  6,  7,  8 ]` (10% 的 "bites" 内容)
    * `0.1 * [90, 100, 110, 120]` = `[ 9, 10, 11, 12 ]` (10% 的 "man" 内容)

  **最后一步：加权求和**

  把上面三个**向量**加起来：
  `Output[0, :]` = `[ (8+5+9), (16+6+10), (24+7+11), (32+8+12) ]`
  `Output[0, :]` = `[ 22, 32, 42, 52 ]`

  **结论**：

    * `Output`（输出张量）的**第 `i` 行**（`[22, 32, 42, 52]`）是一个**新的向量**（长度为 `d_v=4`）。
    * 它**不是** `Attention_Weights` 的第 `i` 行（`[0.8, 0.1, 0.1]`）。
    * 它是通过使用 `Attention_Weights` 的第 `i` 行作为**权重**，去对**所有** `V` 矩阵的行（`V_0`, `V_1`, `V_2`）进行**加权求和**而**计算**出来的。

  这个 `[22, 32, 42, 52]` 向量就是 "dog" (位置 0) 在经过注意力计算后融合了 "80%的自己、10%的'bites'、10%的'man'" 信息后的**新表示**。

- **关于手算和机器算矩阵乘法比较**

  * `Output[0, 0]` (输出矩阵的**第0行第0列**那个**数**) = `Attention_Weights[第0行]` (行向量) **·** `V[第0列]` (列向量)（点积）
  * `Output[0, 1]` (输出矩阵的**第0行第1列**那个**数**) = `Attention_Weights[第0行]` (行向量) **·** `V[第1列]` (列向量)（点积）
  * ...以此类推

  而我上一条回复中描述的**“加权平均值”**，是从一个**不同但数学上完全等价**的角度来描述**同一次**矩阵乘法 `Output = Attention_Weights @ V`。

  这个角度关注的是如何**一次性计算出 `Output` 矩阵的“一整行”**，这在机器学习（尤其是理解注意力机制）中是一个更直观的视角。

  ---

  **为什么这两种说法是等价的？**

  我们用上一条回复中的**同一个例子**来证明：

  **输入：**
  1.  **`A` (Attention_Weights)**，形状 `(3, 3)`
      * `A` 的第 0 行 = `w_row0 = [0.8, 0.1, 0.1]`
  2.  **`V` (Value 矩阵)**，形状 `(3, 4)`
      * `V` 的第 0 行 = `v_row0 = [10, 20, 30, 40]`
      * `V` 的第 1 行 = `v_row1 = [50, 60, 70, 80]`
      * `V` 的第 2 行 = `v_row2 = [90, 100, 110, 120]`
      * `V` 的第 0 列 = `v_col0 = [10, 50, 90]`
      * `V` 的第 1 列 = `v_col1 = [20, 60, 100]`
      * `V` 的第 2 列 = `v_col2 = [30, 70, 110]`
      * `V` 的第 3 列 = `v_col3 = [40, 80, 120]`

  **目标：** 计算 `Output = A @ V` 的**第 0 行**（即 `Output[0, :]`）。

  ---

  **视角 1：按您的记忆（“行乘以列”），逐个计算元素**

  * **`Output[0, 0]`** = `A[第0行]` · `V[第0列]`
      = `[0.8, 0.1, 0.1]` · `[10, 50, 90]`
      = `(0.8 * 10) + (0.1 * 50) + (0.1 * 90)`
      = `8 + 5 + 9` = **`22`**
  * **`Output[0, 1]`** = `A[第0行]` · `V[第1列]`
      = `[0.8, 0.1, 0.1]` · `[20, 60, 100]`
      = `(0.8 * 20) + (0.1 * 60) + (0.1 * 100)`
      = `16 + 6 + 10` = **`32`**
  * **`Output[0, 2]`** = `A[第0行]` · `V[第2列]`
      = `[0.8, 0.1, 0.1]` · `[30, 70, 110]`
      = `(0.8 * 30) + (0.1 * 70) + (0.1 * 110)`
      = `24 + 7 + 11` = **`42`**
  * **`Output[0, 3]`** = `A[第0行]` · `V[第3列]`
      = `[0.8, 0.1, 0.1]` · `[40, 80, 120]`
      = `(0.8 * 40) + (0.1 * 80) + (0.1 * 120)`
      = `32 + 8 + 12` = **`52`**

  **结果 (第 0 行)**：`[22, 32, 42, 52]`

  ---

  **视角 2：按我的讲解（“行的加权求和”），一次计算整行**

  `Output[0, :]` = (`A[0,0]` * `V[第0行]`) + (`A[0,1]` * `V[第1行]`) + (`A[0,2]` * `V[第2行]`)

  * `A[0,0]` 是 `0.8`。`A[0,1]` 是 `0.1`。`A[0,2]` 是 `0.1`。
  * `V[第0行]` 是 `[10, 20, 30, 40]`
  * `V[第1行]` 是 `[50, 60, 70, 80]`
  * `V[第2行]` 是 `[90, 100, 110, 120]`

  **计算：**
    `0.8 * [10, 20, 30, 40]` = `[  8,  16,  24,  32 ]`
  + `0.1 * [50, 60, 70, 80]` = `[  5,   6,   7,   8 ]`
  + `0.1 * [90, 100, 110, 120]` = `[  9,  10,  11,  12 ]`
  -----------------------------------------------------
  **求和 (Sum)** = `[ (8+5+9), (16+6+10), (24+7+11), (32+8+12) ]`
  **结果 (第 0 行)** = `[  22,    32,    42,    52 ]`

  ---

  **结论：**

  您看，两种方法得到了**完全相同**的结果 `[22, 32, 42, 52]`。

  * **您的记忆（视角 1）** 是矩阵乘法中计算**单个元素**的标准定义。
  * **我的讲解（视角 2）** 是矩阵乘法中计算**一整行**的等价定义，也称为“**行的线性组合 (Linear Combination of Rows)**”。

  在注意力机制 的上下文中，**视角 2（行的加权求和）** 更有助于**直观理解**：它清晰地显示了 `Output[0, :]`（"dog" 的新向量）是如何由 `0.8` 倍的 "dog" 原始向量 + `0.1` 倍的 "bites" 原始向量 + `0.1` 倍的 "man" 原始向量**混合**而成的。

## 3. 讲义中的关键要求与约束

* **实现为函数**：`scaled_dot_product_attention` 应该是一个**函数**，而不是一个类。
* **处理批处理维度**：必须能正确处理 `Q`, `K`, `V` 张量中的任意前导维度 (`...`)。
* **支持掩码**：必须接收一个可选的**布尔 (boolean) 类型**的 `mask` 参数。
* **掩码逻辑**：如果 `mask` 矩阵中某个位置为 `False`，则该位置的注意力权重（`softmax` 输出）必须为 0。这必须通过在 `softmax` **之前**将对应分数设置为 `-inf` 来实现。
* **使用手搓的 `softmax`**：必须调用我们之前实现的 `softmax` 函数，而不是 `torch.softmax`。

# 缩放点积注意力：代码实现讲解

## **代码实现 (源自优秀代码 `hw1-basics/scripts/model.py`)**

```python
# (位于 hw1-basics/scripts/model.py)

# 导入 math 库用于开平方根
import math
# 导入 einops 中的 einsum，它是一种更强大、更可读的张量操作方式
from einops import einsum

def scaled_dot_product_attention(
    Q: Float[Tensor, " ... queries d_k"],
    K: Float[Tensor, " ... keys    d_k"],
    V: Float[Tensor, " ... keys    d_v"],
    mask: Bool[Tensor, " ... queries keys"] | None = None, # 2.1
) -> Float[Tensor, " ... queries d_v"]:
    """Scaled dot-product attention.

    This function implements Eq. 1 of the Transformer paper.
    ... (文档字符串) ...
    """

    # 2.2: 获取 d_k 用于缩放
    d_k = K.shape[-1] 
    
    # 2.3: 计算 Q K^T / sqrt(d_k)
    attention_scores = einsum(Q, K, "... query d_k, ... key d_k -> ... query key") / math.sqrt(d_k) 

    if mask is not None: # 2.4
        # 2.5: 将 mask 为 False 的位置设为 -inf
        attention_scores = torch.where(mask, attention_scores, float("-inf")) 

    # 2.6: 调用我们之前实现的 softmax
    attention_weights = softmax(attention_scores, dim=-1)  # Softmax over the key dimension

    # 2.7: 乘以 V，进行加权求和
    return einsum(attention_weights, V, "... query key, ... key d_v ->  ... query d_v") 
```

-----

## **逐行分析**

### **行 2.1 `mask: Bool[Tensor, " ... queries keys"] | None = None`**

  * **作用**：在函数定义中声明可选的 `mask` 参数。
  * **解释**：
      * 这完全符合讲义 §3.5.4 的要求：“Your implementation should also support an optional user-provided boolean mask”。
      * `Bool[Tensor, " ... queries keys"]` 是一种类型提示，说明 `mask` 必须是一个布尔型（`True`/`False`）张量，并且其形状必须能广播到 `(..., queries, keys)`，这正好是 `Q K^T` 计算出的分数矩阵的形状。

### **行 2.2 `d_k = K.shape[-1]`**

  * **作用**：获取 $d_k$（键/查询 向量的维度）。
  * **解释**：
      * `K` 的形状是 `(..., keys, d_k)`。`K.shape[-1]` 简单地提取了最后一个维度的大小，即 $d_k$。
      * 我们需要这个值来进行后续的“缩放”（除以 $\sqrt{d_k}$）。

### **行 2.3 `attention_scores = einsum(...) / math.sqrt(d_k)`**

这行代码完成了“缩放点积注意力”公式 [cite: 694-699] 中的第一步，即 $Scores = \frac{Q K^T}{\sqrt{d_k}}$。我们可以把它拆解为两个主要部分：

1.  **`einsum(...)`**：计算 $Q K^T$（注意力分数）。
2.  **`... / math.sqrt(d_k)`**：执行“缩放”(Scaled)。

我们将严格按照您要求的格式，对这两个部分分别进行详细解析。

---

#### 第 1 块解析：`einsum(Q, K, "... query d_k, ... key d_k -> ... query key")`

##### (1) 语法点 (Syntax)

* `einsum`：这是 `torch.einsum` 或 `einops.einsum` 函数。它是一种基于“爱因斯坦求和约定”的强大张量操作语法。
* **函数签名**：`einsum(tensor1, tensor2, ..., "equation_string")`。
* **`"equation_string"` (方程字符串)**：这是 `einsum` 的灵魂。它由两部分组成，用 `->` 分隔：
    1.  **输入侧 (`... query d_k, ... key d_k`)**：
        * `... query d_k`：这是对第一个输入 `Q` 的形状标注。
        * `,`：用于分隔不同的输入张量。
        * `... key d_k`：这是对第二个输入 `K` 的形状标注。
    2.  **输出侧 (`... query key`)**：
        * `->`：分隔符，左侧为输入，右侧为期望的输出形状。
        * `... query key`：这是我们希望 `einsum` 返回的张量的形状标注。

##### (2) 算法逻辑 (Algorithm Logic)

* `einsum` 函数会解析这个方程字符串，以确定要执行什么操作。
* **`...` (省略号)**：`einsum` 将 `...` 识别为任意数量的“批处理维度”（例如 `batch_size`，或者在 MHA 中的 `batch_size, num_heads`）。由于 `...` 同时出现在两个输入和输出中，`einsum` 会**自动保留**这些维度，并在这些维度上**广播**（batch-wise）地执行操作。
* **命名的轴 (Axes)**：
    * `query`：这个轴只出现在第一个输入 `Q` 和输出中。因此，它被**保留**。
    * `key`：这个轴只出现在第二个输入 `K` 和输出中。因此，它也被**保留**。
    * `d_k`：这个轴**同时出现在 `Q` 和 `K` 中**，但**没有出现在 `->` 之后的输出中**。
* **核心逻辑**：当一个轴（如 `d_k`）出现在多个输入中，但没有出现在输出中时，`einsum` 会沿着该轴执行**点积**（即逐元素相乘后求和）。
* **算法总结**：`einsum` 的逻辑是：“保持批处理维度（`...`）不变，保留 `Q` 的 `query` 轴和 `K` 的 `key` 轴作为输出的最后两个轴。沿着 `Q` 和 `K` 共同的 `d_k` 轴，计算它们（`Q` 和 `K`）的点积。”
* 这在数学上**等价于**计算 $Q K^T$ (Q 乘以 K的转置)。

##### (3) 推导思路 (Derivation)

1.  **我们的目标**：计算 $Q K^T$，得到“注意力分数”矩阵。
2.  **分析张量形状**：
    * `Q` (Query)：形状为 `(..., N_q, d_k)`。`N_q` 是查询序列的长度（我们称之为 `query`）。
    * `K` (Key)：形状为 `(..., N_k, d_k)`。`N_k` 是键序列的长度（我们称之为 `key`）。
3.  **标准 PyTorch 实现 (用于对比)**：
    * `K^T` (K的转置)：`K.transpose(-2, -1)`，形状变为 `(..., d_k, N_k)`。
    * `Q K^T` (矩阵乘法)：`torch.matmul(Q, K.transpose(-2, -1))`。
    * **结果形状**：`(..., N_q, N_k)`。
4.  **`einsum` 推导**：
    * 我们如何用 `einsum` 得到 `(..., N_q, N_k)` 的结果？
    * **输入 1 (Q)**：我们标注其形状为 `"... query d_k"` (对应 `..., N_q, d_k`)。
    * **输入 2 (K)**：我们标注其形状为 `"... key d_k"` (对应 `..., N_k, d_k`)。
    * **期望输出**：我们希望得到 `"... query key"` (对应 `..., N_q, N_k`)。
    * **组合字符串**：`einsum(Q, K, "... query d_k, ... key d_k -> ... query key")`。
    * `einsum` 自动完成了 `K` 的转置（通过将 `d_k` 轴进行匹配）和 `matmul`（通过对 `d_k` 轴进行求和）这两个步骤。

##### (4) 迁移技巧 (Migration / Transfer)

* **为什么要用 `einsum`？**
    1.  **可读性**：`einsum(Q, K, "... q d, ... k d -> ... q k")` 比 `torch.matmul(Q, K.transpose(-2, -1))` 更能**自解释**。它明确地*命名*了每个轴（`q`, `k`, `d`），并清晰地展示了操作（`d` 消失了=求和了）。
    2.  **消除 `transpose`**：`einsum` 自动处理了轴的匹配，你不需要在 `matmul` 之前显式地调用 `transpose` 或 `permute`，减少了出错的可能。
* **迁移技巧**：当您未来需要执行复杂的张量操作时（例如，批处理矩阵乘法、张量缩并、带转置的乘法），`einsum` 都是您的首选工具。
    * **矩阵转置**：`torch.transpose(x, 1, 2)` -> `einsum(x, "... i j ... -> ... j i ...")`
    * **逐元素相乘**：`A * B` -> `einsum(A, B, "... i, ... i -> ... i")`
    * **矩阵-向量 乘法**：`torch.matmul(A, v)` -> `einsum(A, v, "i j, j -> i")`

---

#### 第 2 块解析：`... / math.sqrt(d_k)`

##### (1) 语法点 (Syntax)

* `...`：在这一行中，`...` 指代的是 `einsum` 函数返回的**整个结果张量**（即 `attention_scores`）。
* `/`：PyTorch 重载（overload）的标准除法运算符。它执行的是**逐元素 (element-wise) 除法**。
* `math.sqrt(d_k)`：
    * `d_k`：是前面从 `K.shape[-1]` 获取的 Python **整数**。
    * `math.sqrt()`：是 Python 标准 `math` 库中的**开平方根**函数。
    * 结果：一个 Python **浮点数**（float），例如 `math.sqrt(64) -> 8.0`。
* **广播 (Broadcasting)**：这里执行的是一个 `Tensor / float` 操作。PyTorch 会自动将这个**标量 (scalar) 浮点数** `8.0` **广播**到 `attention_scores` 张量的**每一个元素**上，使每一个元素都除以 `8.0`。

##### (2) 算法逻辑 (Algorithm Logic)

* [cite_start]**目的**：这就是“缩放点积注意力”中**“缩放” (Scaled)** 的来源 [cite: 694-699]。
* **算法**：获取原始的、未归一化的注意力分数（来自 $Q K^T$），并将**每一个**分数都除以 $\sqrt{d_k}$。
* **原因**：防止 `softmax` 函数进入饱和区。讲义理论中提到，当 `d_k` 很大时（例如 64、128），$Q K^T$ 的点积结果的**方差**也会变得很大（方差约为 `d_k`）。
* **后果**：
    * 如果分数（logits）变得非常大（例如 `+500`）或非常小（例如 `-500`），`softmax` 函数的输出会趋近于 1 或 0。
    * 在这些“饱和”区域，`softmax` 的**梯度**（导数）几乎为 0。
    * 在反向传播时，梯度为 0 意味着模型**无法学习**（即梯度消失）。
* **我们的逻辑**：通过除以 $\sqrt{d_k}$，我们将分数的方差重新拉回（“缩放”）到 1 左右，确保 `softmax` 在其“敏感区”（梯度较大的区域）工作，从而使训练**更加稳定**。

##### (3) 推导思路 (Derivation)

1.  **假设**：假设 `Q` 和 `K` 中的元素（`q_i`, `k_i`）是均值为 0、方差为 1 的独立随机变量。
2.  **点积**：$Score = \sum_{i=1}^{d_k} q_i k_i$
3.  **方差分析**：
    * $Var(q_i k_i) = Var(q_i)Var(k_i) + Var(q_i)E[k_i]^2 + Var(k_i)E[q_i]^2$
    * 由于均值 $E[q_i]=E[k_i]=0$，方差 $Var(q_i)=Var(k_i)=1$：
    * $Var(q_i k_i) = 1 \cdot 1 + 1 \cdot 0^2 + 1 \cdot 0^2 = 1$
4.  **方差求和**：`Score` 是 $d_k$ 个这样的独立随机变量的和。
    * $Var(Score) = Var(\sum_{i=1}^{d_k} q_i k_i) = \sum_{i=1}^{d_k} Var(q_i k_i) = \sum_{i=1}^{d_k} 1 = d_k$
5.  **问题**：分数的方差是 $d_k$。如果 $d_k=64$，标准差 $\sigma = \sqrt{64} = 8$。这意味着分数很容易偏离 0 很远。
6.  **目标**：我们希望将 $Score$ 的方差缩放回 1。
7.  **求解**：我们需要找到一个缩放因子 $c$，使得 $Var(c \cdot Score) = 1$。
    * 根据方差性质：$Var(c \cdot X) = c^2 \cdot Var(X)$
    * $c^2 \cdot Var(Score) = 1$
    * $c^2 \cdot d_k = 1$
    * $c^2 = 1 / d_k$
    * $c = 1 / \sqrt{d_k}$
8.  **结论**：我们必须将 $Score$（即 $Q K^T$）**除以 $\sqrt{d_k}$**。
9.  **代码实现**：`... / math.sqrt(d_k)` 正是这一推导的直接代码转换。

##### (4) 迁移技巧 (Migration / Transfer)

* **核心原则**：当您计算点积并将其作为输入送入非线性激活函数（尤其是 `softmax` 或 `sigmoid`）时，**一定要考虑其方差**。
* **迁移**：这个 $\sqrt{d_k}$ 缩放因子是 Transformer 成功的关键秘诀之一。它不仅限于注意力。
    * **权重初始化**：Kaiming 初始化和 Xavier 初始化也是基于类似的原理（保持方差为 1）来缩放权重矩阵的。
    * **构建新模型**：如果您未来发明自己的注意力变体，（比如用 `Q+K` 或 `Q*K` 代替 $Q K^T$），您必须重新分析其输出的方差，并设计一个新的、合适的缩放因子，以确保训练稳定。
* **代码实践**：`math.sqrt(d_k)` 计算的是一个标量。使用 `d_k**0.5` 也是完全等价的。将 `d_k` 作为一个 Python `int` 传递并使用 `math.sqrt()` 是非常干净且高效的，因为这个标量浮点数可以被 PyTorch 自动广播到整个分数矩阵上。

### **行 2.4 & 2.5 `if mask is not None: ... torch.where(mask, attention_scores, float("-inf"))`**

  * **作用**：**应用掩码**，这是讲义中的一个关键要求。
  * **解释**：
      * `torch.where(condition, x, y)` 是 PyTorch 中的三元运算符。它会查看 `condition` (即 `mask`)：
          * 如果 `mask` 在 `[i, j]` 位置为 `True`，它就保留 `x` (即 `attention_scores[i, j]`) 的原始分数。
          * 如果 `mask` 在 `[i, j]` 位置为 `False`，它就使用 `y` (即 `float("-inf")`)。
      * 这正是讲义所要求的：“在 `softmax` **之前**...在掩码矩阵为 `False` 的任何条目上**加上 -∞**”。
      * 为什么是 `-inf`？因为在下一步 `softmax` 中，`exp(-inf)` 会变为 `0`，从而确保被掩码的位置在加权求和中的权重为 0。

### **行 2.6 `attention_weights = softmax(attention_scores, dim=-1)`**

  * **作用**：将（可能已被掩码的）原始分数转换为概率分布。
  * **解释**：
      * 这里我们**重用**了在 `model.py` 顶部实现的、我们刚学过的 `softmax` 函数。
      * `dim=-1` 至关重要。它告诉 `softmax` 沿着最后一个维度（即 `key` 维度）进行归一化。
      * 效果是：对于**每一个** `query` 向量（`query` 维度），它对**所有** `key` 向量的注意力分数之和为 1。

### **行 2.7 `return einsum(attention_weights, V, "... query key, ... key d_v -> ... query d_v")`**

  * **作用**：实现公式的最后一步：$... V$（加权求和）。
  * **解释**：
      * `einsum` 再次登场！
      * `attention_weights` (权重) 的形状是 `"... query key"`
      * `V` (值) 的形状是 `"... key d_v"`
      * `->` 之后是输出的形状 `"... query d_v"`
      * `einsum` 再次分析：
        1.  `...` 和 `query` 维度被保留。
        2.  `d_v` 维度被保留。
        3.  `key` 维度同时出现在 `weights` 和 `V` 中，但**没有**出现在输出中。
      * 因此，`einsum` 会沿着 `key` 维度执行点积（乘法并求和）。
      * 这完美地实现了**加权求和**：对于每个 `query`，它将 `V` 矩阵中的所有 `key` 向量（`d_v` 维度）按照 `attention_weights` 进行了加权平均。
      * 输出的形状 `(..., query, d_v)` 正是我们所期望的。
